The submission form, field by field

The platform dialog (“New submission”) asks for exactly two things:

FieldWhat to enter
File to submit The submission.tif downloaded above. A single-band GeoTIFF is accepted directly (a .zip containing one GeoTIFF also works). It must match the submission format's CRS, shape and geotransform — ours is generated from the official template, so it does.
Note (optional) halo r15/h0.6 + blind GBT v1 (7GEMSDOE)
A unique, descriptive comment so the team can tell submissions apart later (the form's own example: “clustering with k=25”). Change the version tag per artifact.

Then press submit. Scores appear on the public leaderboard (public-set DW-Tversky). Limit: three submissions per week (rules PDF).

Step-by-step

  1. Sign in to DrivenData and open the competition: competition-doe-gems.
  2. Download submission.tif from this page and (optionally) check its sha256 against the value in Step 0.
  3. Open Submit → New submission.
  4. File to submit: choose submission.tif.
  5. Note: paste the suggested note above (or your own unique tag).
  6. Submit. Watch the public leaderboard for the DW-Tversky score.
  7. Before the deadline, choose the single submission that counts for both prize rounds (you will not see private scores when choosing — rules §prize structure).

Why earlier submissions failed validation, and why this one cannot

The platform rejection “Predicted values must be in range [0, 1]” fires when the raster contains any pixel that is not a finite number in [0, 1] inside the scored footprint — in practice, NaN leaking into the footprint. Our build enforces the opposite geometry and re-reads the written bytes:

Requirement (problem page)How it is enforced
single band, float32written from the official template metadata; gate checks dtype/count
CRS EPSG:32611, same bounds & geotransformcopied verbatim from example_submission.tif; gate compares exactly
values between 0 and 1hard clip before write; gate asserts min ≥ 0, max ≤ 1 on all finite pixels
outside bounds = null/NaNNaN exactly on the template's footprint complement; gate asserts finite-inside / NaN-outside

Gate: scripts/validate_submission.py (also runnable standalone against any candidate and the official template). Regression tests: tests/test_submission_format.py.

Generating new submission files

bash scripts/download_competition_data.sh    # once per machine
.venv/bin/python scripts/extract_features.py
.venv/bin/python scripts/train_model.py
.venv/bin/python scripts/build_submission.py # rebuild downloads/submission.tif + meta

Every artifact carries its policy, sha256, build time and monitors in downloads/submission_meta.json — paste a unique version tag into the Note field for each.

Strategic reminder: both prize rounds score NEW faults absent from the public catalogue (rules §1.1, §3.3, §3.5 — verbatim quotes in Research). A public-leaderboard score is a partial signal; the private set decides the Initial Prize Round, and expert review of every submission expands the labels for the Final Round. Pick your selected submission accordingly.
