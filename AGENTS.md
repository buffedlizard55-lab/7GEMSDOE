# Start every session here

1. Read README.md (mission brief), STATUS.md, knowledge/session4/review.md and current
   machine evidence before changing models or prose.
2. Maximize P(Win): prioritize independent discovery signal and valid reproducible
   submissions over cosmetic changes or public-score chasing. Own the outcome:
   verify end-to-end downloads, tests and source provenance; record failures.
3. Never equate fault predictions with verified geothermal vent discoveries.
4. Label official-source facts, team reports, local measurements and untested
   hypotheses separately. Do not promise leaderboard gains. Link primary evidence.
5. Use one participating entity's rules-compliant feedback budget. Never multiply
   uploads across team accounts or assert account eligibility without evidence.
6. Large datasets stay in GEMS_DATA_DIR (default ~/gems_data), not Git. Publish only
   small manifests/reports and consciously selected, format-gated submission files.
7. Preserve the control and frozen test protocol; name new artifacts by policy+hash.
8. Run three passes: implement/test; inspect bugs/assumptions/edges; check the full
   request and end-to-end outcome. Record limitations and next steps.

9. Read knowledge/session3/next_session.md. Do not promote H3 on the old component
   proxy: its geographic coverage failed. Do not call the four inspected diagnostic
   quadrants an untouched final test. Preserve raw expert results and source caveats.

10. Read knowledge/session4/next_session.md. External/official data that the sandbox
    cannot reach is processed on GitHub Actions and only compact, provenance-logged
    products are committed. Local skill on catalogue faults is not a leaderboard
    estimate. Emit thin lines, never blobs; record every upload's SHA-256 and score.
